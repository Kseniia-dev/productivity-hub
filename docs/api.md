# API Draft

## Auth

### Входит в MVP

Пользователь регистрируется через email.

Для входа пользователю нужны email + password.

MVP можно пользоваться без регистрации как гость.

Если гость создаёт задачи, то перед закрытием браузера ему выходит предупреждение, что задачи не сохранятся и для их сохранения нужно зарегистрироваться.

После входа пользователь попадает на главную страницу с календарём.

Если будет введён неверный пароль, то пользователю будет показано сообщение, что был введён неправильный пароль.

Предложение перейти на страницу с восстановлением пароля.

## Users

### Входит в MVP

У пользователя есть такие поля: email, username, role, дата регистрации.

Пользователь может менять username.

Пользователь может менять пароль в MVP.

Менять роль пользователя может только администратор.

Роли, которые точно нужны в MVP: guest, user, admin.

Guest может видеть главную страницу с календарём, создавать задачи, выполнять их, использовать сессии фокусировки, но не сможет получить статистику по выполненным задачам или сохранить задачи и прогресс после закрытия браузера.

User может создавать задачи, выполнять задачи, заходить в свой ЛК, использовать сессии фокусировки, смотреть свою статистику по выполненным задачам в ЛК.

В ЛК пользователь видит username, email, роль, количество задач на текущий день, количество выполненных вовремя задач и кнопку смены пароля.

### Будет реализовано позже

Пользователь может менять email, привязав другой.

Обычный пользователь может видеть профили с основной информацией других пользователей и их статистику по выполненным вовремя задачам.

User может просматривать профили других пользователей.

Возможность загружать фото профиля.

## Tasks

### Входит в MVP

Задача - сущность с названием, длительностью, статусами, которые задаёт пользователь.

Задача всегда привязана к конкретной дате.

Задача не обязана иметь время начала, длительность или описание.

Статусы задачи: planned, in_progress, done, undone, cancelled.

Пользователь может удалить задачу, она реально удалится.

Можно создать несколько задач на одно и то же время, но запускать можно не одновременно.

Если длительность задачи указана, она должна быть больше нуля.

Если на выбранную дату нет задач - показываются просто пустые ячейки для задач.

Пользователь не может видеть задачи другого.


### Будет реализовано позже

Будет функция перенести задачу на другой день до 3-х раз, после чего она будет помечена как невыполненная.

Админ может видеть задачи всех пользователей.

## Focus Sessions

### Входит в MVP

Сессию фокусировки можно запустить как без задачи, так и для конкретной задачи.

Пользователь выбирает сколько будет длиться период фокусировки и перерыв между ними, а также время, которое нужно провести в фокусе.

Состояния: running, paused, completed, cancelled.

Нужно сохранить незавершённую фокус-сессию.

Сессия считается завершённой, если прошло изначально отведённое время на фокусировку.

Если пользователь ставит период фокусировки на паузу, то мы сохраняем результат и после возобновления продолжаем отсчёт времени.

Хранится кол-во завершённых циклов фокусировки и общее время, проведённое в фокусе без учёта времени перерывов.

Можно показывать историю сессий фокусировки за день.

Если пользователь обновит страницу во время таймера, то он продолжит отсчёт времени.

После завершения фокуса приложение предлагает отметить задачу как done

Связь между завершением задачи и завершением фокус-сессии будет расширена позже.

## Admin

### Входит в MVP

Админ должен в отдельной админ-панели видеть кол-во зарегистрированных пользователей, общее кол-во тасков пользователей, сессий с фокусировкой, сколько всего выполненных тасков отмечено.

Админ может менять роли.

Нужна отдельная админ-страница на frontend.

Обычный пользователь не может менять роли, блокировать пользователей и заходить в админ-панель.

### Будет реализовано позже

Админ может блокировать пользователей.
